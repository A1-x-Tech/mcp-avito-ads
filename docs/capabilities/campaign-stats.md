# Авито Реклама: Статистика кампании — MCP-инструмент (tool)

**MCP-инструмент (tool) для Авито Рекламы:** Статистика ОДНОЙ кампании за период дат с разбивкой по группам и креативам: {campaign, groups[], creatives[]}.

Техническое имя: `campaign_stats`

## Какую задачу решает

> Я хочу посмотреть статистику кампании.

Статистика ОДНОЙ кампании за период дат с разбивкой по группам и креативам: {campaign, groups[], creatives[]}.

## Когда использовать

Используйте эту возможность, когда нужен результат «Статистика кампании» без ручной работы в интерфейсе Авито Рекламы. Операция выполняется только по вызову из AI-приложения.

## Что нужно передать

- `campaignId` — **обязательно**. Кампания, по которой строится отчёт. Id можно найти через list_campaigns.
- `dateFrom` — **обязательно**. Первый день периода, включительно (YYYY-MM-DD).
- `dateTo` — **обязательно**. Последний день периода, включительно (YYYY-MM-DD). Должен быть >= dateFrom, а период — не длиннее 100 дней.

## Что вернёт

Возвращает компактный JSON-ответ исходного API или понятную ошибку MCP-инструмента. Точный состав полей зависит от операции и описан в техническом справочнике.

## Что изменится в Авито Рекламе

Инструмент только читает данные или состояние подключения и не изменяет их.

## Пример запроса

> Посмотреть статистику кампании в Авито Рекламе. Если не хватает обязательных идентификаторов, сначала уточни их.

## Возможные ошибки и ограничения

У каждой сущности есть data[] (по строке на день, с отметкой timestamp) и totalData (итог за период). Метрики в строке: views (показы), clicks (клики), ctr, spend (расход), spendBonus, cpm, cpc, а для видеокампаний ещё videoViews25/50/75/100, q25/q50/q75 и vtr; деньги в рублях, коэффициенты передаются как есть. Период включает обе границы, формат YYYY-MM-DD, длительность не больше 100 дней. Сводить несколько кампаний вместе не умеет, гранулярности мельче дня нет; campaignId даёт list_campaigns. Тратит недельные баллы API; apiPointBalance в ответе — остаток до пополнения квоты в понедельник в 00:00 UTC, поэтому один широкий период предпочтительнее многих узких вызовов.

Доступ также зависит от прав токена, квот и ограничений исходного API.
